说明与限制
  • 容器 xiaomi-plugin-transmission 只挂载所选的配置、下载、监控目录，不挂载 Docker socket，不使用 privileged 或 host 网络。
  • WebUI 端口 9091（TCP）对局域网开放；BT 入站端口 51413（TCP/UDP）已映射，公网入站仍需在路由器转发。
  • 「打开控制台」为插件内置界面，通过 Transmission JSON-RPC 拉取任务；卡片里的 9091 地址是官方 WebUI 直连入口。
  • 配置文件是 —：容器里的 daemon 由镜像以 transmission-daemon -g /config 启动，只读这个文件。改配置请先点「停止服务」， 改完再「启动服务」——服务运行时改会被 daemon 退出时写回的值覆盖。
  • 插件不会覆盖你改过的值：启动时只补缺失的键，缓存、连接数、限速、DHT/PEX、队列等改了就是你的值； 只会纠正 rpc-enabled、rpc-port、rpc-bind-address 这三个与容器端口映射绑定的键。
  • 账号密码、白名单、BT 端口、umask 由镜像每次启动按容器环境变量重写，改 settings.json 里的这些键无效（换账号密码需重新初始化插件）。
  • 停止或卸载插件只停止容器，配置与已下载文件都会保留。
  • 检测到旧版遗留配置 —，daemon 不会读取它； 请改上面的 settings.json。

重新初始化？

这会清空本插件的配置、停止并移除 Transmission 容器（daemon 的 settings.json 只另存一份备份， 原文件保留；插件的 credential.json 会归档成 credential.json.bak-<时间戳>，不会删除）， 并撤掉路由器上的端口映射，页面回到初始化表单，之后需要重新初始化才能再次启动服务。

下载、配置、监控目录里的文件不受影响：不会被删除、移动或改写（种子与 resume 数据都留在配置目录里），请放心。

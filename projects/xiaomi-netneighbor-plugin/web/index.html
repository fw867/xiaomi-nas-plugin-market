账号的共享目录

给账号再加一个目录

必须是 NAS 上已存在、且在允许根目录内的绝对路径。

命令实际执行的是 smb_mgr.sh shares add_dir <账号_nb_序号> <路径> "<账号>" <显示名> [force_user]， 然后由插件自己跑 init_config + systemctl reload smb nmb 并核对配置是否生效。

说明与限制
  • 发现服务的原理：官方 /usr/bin/wsdd 发出的消息缺 wsd:AppSequence，而且它的元数据服务不响应 WS-Transfer Get（SOAP POST），所以 Windows 拿不到设备描述、 不把它列出来。插件启动时先 systemctl stop wsdd（并用 pkill -x wsdd 兜底），再用一个 systemd drop-in （/etc/systemd/system/wsdd.service.d/netneighbor.conf） 把官方单元改成空操作，然后在插件进程内跑完整的 WSD 服务端 （Hello/Bye/ProbeMatches + 元数据 HTTP）。
  • 用 drop-in 而不是 systemctl mask：mask 之后官方 smb_mgr.sh 收尾那句 systemctl restart wsdd 会失败并让整条命令返回 1，用户在手机端保存共享时会看到失败提示 （虽然配置其实已经写好）。空操作 drop-in 让 restart 依旧返回 0。
  • 插件停止（或卸载）时会先发 Bye，再删掉 drop-in、 daemon-reload 并 start wsdd，系统回到原样。
  • 插件新增的共享只用 <账号>_nb_<序号> 命名， 不会和 App 生成的 <账号>_<id> 冲突； 删除也只允许删这一族。
  • 添加/删除共享后，Samba 会 reload，已经连上的 Windows 客户端建议 断开重连（或在资源管理器里刷新）才能看到新共享。

网络模式与数据持久化

配置目录挂载为容器内 /config，Home Assistant 的数据库、集成配置、自动化与密钥都在这里；留空时在插件私有目录。

Home Assistant 会把 /config 下的 media、share、ssl、backup 当成普通子目录，所以不需要再单独挂载媒体目录。

网络：容器使用 host 网络，直接用宿主机的 8123（不做端口映射，容器内外是同一个端口）。这样 Home Assistant 的自动发现（mDNS/SSDP）与来源地址判断才是完整的。

基本配置在首次打开面板时完成初始化流程并创建管理员账号。

说明与限制
  • 容器 xiaomi-plugin-homeassistant 只挂载所选配置目录，不挂载 Docker socket，不使用 privileged。
  • 网络模式是 host：容器与宿主机共享网络栈，直接用宿主机的 8123（不做端口映射）——Home Assistant 的自动发现与来源地址判断需要它。代价是隔离性弱于桥接；资源上限与 no-new-privileges 仍然保留。
  • 数据持久化：/config（数据库、集成配置、自动化、密钥；media/share/ssl/backup 都是它下面的子目录）。
  • 端口：宿主机 8123（Web UI / API），对局域网开放；插件页面自己用 18200，两者不冲突。
  • 镜像会按 Docker 版本自动选：厂商 Docker 是 20.10，不支持 zstd 压缩层，而 Home Assistant 从 2026.3.0 起的镜像是 zstd 层（拉取会报 failed to register layer … invalid tar header）。所以 Docker < 23 时插件自动固定到最后一个 gzip 层版本 2026.2.0；等厂商把 Docker 升到 23+，插件会自动回到最新的 stable，不需要改任何配置。当前用的是哪个镜像、为什么，见上方状态卡片。
  • Home Assistant 官方容器以 root 运行（镜像不支持非 root 用户，也没有 PUID/PGID）。所以初始化时要求配置目录属于非 root 的 NAS 用户：HA 在容器里写入的文件，在宿主机上仍然归那个用户，小米客户端的文件管理才能正常显示与操作。
  • Home Assistant 为开源软件，本插件不代表官方背书。
  • 停止或卸载插件只停止容器，配置目录里的文件都会保留。
  • 容器健康检查是关闭的：官方镜像每 30 秒打一次 HTTP 探针，每打一次 Home Assistant 都会重写 SQLite，进而唤醒系统索引和硬盘（约 1.4 GB/天/盘）。插件建的容器不再带这个检查；服务是否可用由上面的就绪状态反映。
  • 首次使用：用浏览器打开入口地址完成初始化（创建管理员账号）。初始化完成前同网段设备可能抢先注册，请尽快设置。

# 控制台（小米智能存储社区插件）

一个桌面式的 NAS 控制台：硬件状态、硬盘与 SMART、Docker 容器、系统服务与已装应用，
外加一个**可读写**的文件窗口。两个入口分工明确：

| 入口 | 地址 | 内容 | 鉴权 |
| --- | --- | --- | --- |
| 电脑浏览器（桌面版） | `http://<NAS_IP>:5001/`（端口可在手机端改） | 桌面图标 + 弹出窗口 + 右侧组件栏 | 安装时生成的访问令牌 |
| 小米客户端（手机端） | 「全部应用」→ 控制台（`/plugin/<用户>/nasconsole/`） | **开关、访问地址、端口设置、访问令牌（可重新生成）** | 客户端证书 + 令牌，由 nginx 完成 |

手机端刻意不显示面板内容——桌面版要专注做成桌面 OS 的样子，手机上放开关、端口和令牌最实用。
版式跟其它插件（内网穿透、设备管家等）保持一致：**贴顶的 sticky 顶栏**（插件图标 + 名称 +
`nasconsole` 副标题 + 右侧状态胶囊）、内容紧接其下，版本号居中放在页面底部，不单独占一张卡片。

**非小米官方产品。** 写操作只有三类，都限制在白名单目录内：
① 「桌面 Web 控制台」开关与端口（改自己那一个 nginx 配置文件）；
② 文件窗口的上传 / 新建文件夹 / 重命名；
③ 删除（**先移到回收站**，可恢复；彻底删除需要二次确认）。
不写 NAS 配置、不启停服务、不启停容器。

## 为什么要有它

设备管家已经能看硬件指标，插件市场能装应用，但它们分散在两个入口里，
而且都只能从小米客户端打开。控制台要解决的是：

- **一个电脑浏览器页面**看全机状态（不用装客户端、不用 SSH），且做成桌面系统的观感；
- **一眼看到硬盘状态**：休眠/活动、盘温、SMART 关键项——排查休眠问题最需要的信息；
- **看到容器与服务的真实运行情况**，而不是"应用显示正在运行"；
- **手机上能开关桌面入口、查看令牌**，不用登 SSH。

## 它不做的事

- 不改任何系统配置（`uci`、`hdidle`、`findex` 等都只读）；
- 不启停容器或服务；
- 不做复制 / 移动 / 解压（文件窗口目前是浏览 + 预览 + 上传 + 重命名 + 删除）；
- 不为了读 SMART 把休眠中的硬盘唤醒（见下）。

它**唯一**的写操作是「桌面 Web 控制台」开关：启用/停用自己那个 nginx 入口配置文件。

## 开关、端口与令牌（手机端页面）

**开关**（唯一的配置类写操作）

- 启用：把插件目录里的模板渲染成当前端口后原子写入
  `/etc/nginx/conf.d/xiaomi-nas-console-lan.conf`；
- 停用：删除该文件；
- 两步都会先 `nginx -t`，失败立刻回滚，再 `systemctl reload nginx`；
  重载失败也回滚。**绝不会留下坏配置**（`nginx -t` 通过才会 reload）。
- 停用后端口不再监听（连接被拒），手机端和其它插件不受影响，随时可以在手机上再打开。

**端口**

- 默认 **5001**，可以在手机端页面直接改（1024–65535）。
- 改动同样走"渲染模板 → `nginx -t` → reload"，失败回滚；端口被占用会直接拒绝。
- 一致性：`lan_port()` **以已安装的 nginx 配置为准**（那才是真正在监听的端口），
  没有配置时才看状态文件 `/data/plugin/xiaomi-nas-console/state.json`。
  安装脚本也会读这个状态文件——重装不会把你在 App 里设的端口改回默认值。
- 端口可用性检测带 `SO_REUSEADDR`：刚关掉的端口不会因为 TIME_WAIT 被误判占用，
  但真正在 LISTEN 的端口照样能检出（实测 5000/5001 占用、5099 可用）。
- 从**旧端口**的浏览器页面改端口时，改完这个页面自己就连不上接口了——保存成功的提示里
  带着新地址，按新地址重新打开即可；**从小米客户端操作完全不受影响**
  （客户端页面是它自己代理进来的，和入口端口无关）。

**令牌**

- 手机端用**输入框 + 框内右侧的眼睛图标**展示令牌：默认掩码（`type=password`），
  点眼睛切换明文/掩码，图标同步变成"眼睛加斜线"，`aria-pressed` / `aria-label` 跟着变；
  旁边仍是「复制」与「重新生成」。
- 手机端可以**重新生成**访问令牌（两击确认，避免误点）；新令牌立即写盘（0600）并
  替换服务内存里的会话密钥，**所有已登录的浏览器会话立即失效**，需要用新令牌重新登录；
- 手机端页面本身走客户端证书，不受令牌轮换影响。

写操作的鉴权：小米客户端入口（客户端证书）与本机回环直连视为可信；
浏览器入口必须已登录并且带 CSRF 令牌。

### 桌面入口与插件页面的关系（重要）

插件的网页本来就只挂在 **443**（小米客户端证书 + 令牌 + `plugin.cgi` 鉴权）。
桌面入口需要能打开它们，但插件的信任判断是这样的（以 Jellyfin / Transmission /
Emby / qB / 内网穿透为例）：

> 客户端证书 DN 匹配 `CN=nas.<用户数字>.`，**或者 X-Real-IP 是回环地址**，才认为请求可信；
> 否则页面与接口一律 401「请从设备所有者的小米客户端重新打开插件」。

所以桌面入口对 `/plugin/` 的处理是**绕本机 443 一跳**：

```nginx
location ^~ /plugin/ {
    proxy_pass https://127.0.0.1$request_uri;   # 443 上有同一批插件路由，插件看到的来源是回环
    proxy_ssl_verify off;
    proxy_set_header Authorization "Bearer console-loopback";  # 过 443 那道"凭据之一"门槛
    ...
}
```

这样插件走的是**它们本来就给本机安装器留的那条回环信任路径**，页面和接口都正常
（不这么做的话，Jellyfin 这类插件的页面会渲染成拒绝态）。

代价要说清楚：**走 8085 打开插件页面不需要客户端证书，凭据是桌面令牌**。
拿到桌面令牌的人可以操作这些插件界面（与拿到客户端证书的操作者同级）。所以：

- 不要把这个端口转发到公网；
- 不想这样用时，**在手机端把「桌面 Web 控制台」关掉即可**——桌面入口与这些插件页面会一起停掉；
- 桌面只列出**探测确认能在网页里打开**的插件；控制台自己（nasconsole）不会重复出现。

## 不打扰硬盘

这台机器上「硬盘不休眠」几乎是所有性能/功耗问题的根源，所以采集层刻意做了约束：

- 高频轮询（默认 2 秒）只读 `/proc`、`/sys`，不产生任何磁盘 I/O；
- 硬盘电源状态用 `hdparm -C` 查询——该 ioctl 不会唤醒硬盘（与硬盘休眠插件同一结论）；
- **硬盘处于 standby 时跳过 SMART 与盘温**，页面上显示"温度待唤醒后读取"；
- SMART 结果缓存 5 分钟；
- Docker 统计缓存 15 秒，且只在打开「容器」窗口时拉取。

历史曲线由服务端采样线程维护（2 秒一个点，保留 5 分钟），页面切到后台时停止轮询。

## 页面

**电脑端**是桌面 OS 的样子：彩色壁纸 + 左侧桌面图标 + 右侧常驻组件栏。
**打开页面先看到桌面本身（图标 + 右侧组件栏），不会自动弹出窗口**；点图标才开窗口。
窗口是浮动的（可拖动、可最大化、可最小化、可关闭，多个窗口可以同时开着，
顶栏中间是窗口列表，点一下聚焦/恢复）。

**右侧组件栏**（常驻，一眼可见）

- 运行状态：CPU / 内存双环、本次运行、CPU 温度、硬盘温度、系统负载；
- 网络：实时上下行 + 5 分钟曲线；
- 存储读写：R / W 速率 + 曲线；
- 存储空间：NAS 自己的存储优先（数据盘 → 系统区 → 内置盘）。

**五个窗口**

- **概览**：最近 5 分钟曲线（CPU / 内存 / 网络 / 磁盘 I/O 可切换）、硬盘休眠状态、系统信息。
- **磁盘**：每块物理盘的型号、容量、电源状态、温度、通电时间、重映射/待映射扇区、
  SMART 健康；所有挂载点的容量条；md 阵列状态与同步进度。
- **文件**：浏览 NAS 上的目录（面包屑导航、当前目录筛选、按目录优先排序），
  右侧预览面板能直接看图、看文本（前 256 KB）、下载任意文件、复制路径；
  **可以上传**（点按钮或把文件拖进列表，带进度，重名会让你确认覆盖）、
  **新建文件夹**、**重命名**、**删除**。删除是**移到回收站**：同一个存储根下的
  `.console-trash/`（同盘 rename，瞬间完成），窗口里的「回收站」可以恢复或彻底删除
  （彻底删除要勾选确认）。
- **容器**：Docker 版本与镜像数，容器列表（状态、镜像、端口、CPU/内存/网络/IO）。
  系统容器（`miot_central`）会被标出来。
- **系统**：已装插件（编号、版本、界面版本、服务状态）、关键系统服务开关状态、
  硬盘休眠设置、会周期性碰硬盘的厂商定时任务。

桌面图标一共 5 个：概览 / 磁盘 / 文件 / 容器 / 系统，后面接着已安装的插件图标。
「入口设置」不在桌面上（端口、令牌、开关都在手机端页面上操作）。

**已安装的应用直接摆在桌面上**：图标区里紧跟系统图标之后，用的是插件自己的图标
（`/data/plugin/www/icon/`，小米客户端用的是同一个）。点一下就在窗口里用 iframe
打开那个插件的真实页面——和 App 里点开是一样的东西，实测 8 个都可操作：
**设备管家、插件市场、SSH 开关、Transmission、Jellyfin、内网穿透、硬盘休眠、网络邻居**。

只有小米客户端里有界面的应用（影视 / 中枢功能 / 监控存储 / 百度网盘 / 迅雷）
**不会出现在桌面上**（它们仍然列在「应用」窗口的清单里，说明它们只能在客户端里开）。
图标不单独分组：和系统图标排在同一列流里，一列放不下自动排到第二、第三列，
图标区没有滚动条。

窗口默认按桌面区域的比例打开（约 74%×88%，高清屏自动更大），可以拖标题栏移动、
拖右下角/边缘缩放、最大化、最小化（顶栏中间会列出已打开的窗口），多个窗口可以叠放。
左侧图标列独立于窗口区域，因此窗口永远不会挡住图标。

窄屏（手机浏览器打开桌面入口）只显示一句提示和地址，请改用电脑打开。

**手机端**（小米客户端里的那个页面）：一个开关、访问地址（复制/打开）、访问令牌（显示/复制）、
版本与设备信息。界面不引外部资源（字体/图标/CSS 全在本地，壁纸是纯 CSS 渐变，
图标是内联 SVG 渐变），可以在严格 CSP 下工作；动态样式走 CSSOM 写入，不用内联 `style` 属性。

## 接口

服务只监听 `127.0.0.1:18100`，由 nginx 反代。

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/healthz` | GET | 存活检查 |
| `/api/session` | GET | 入口类型与登录状态 |
| `/api/overview` | GET | CPU、内存、温度、网络、磁盘 I/O、硬盘电源状态（快，2 秒轮询） |
| `/api/history` | GET | 最近 5 分钟曲线（CPU / 内存 / 网络 / 磁盘） |
| `/api/storage` | GET | 硬盘 SMART、挂载容量、md 阵列 |
| `/api/docker` | GET | 容器列表与资源（`?stats=0` 可跳过统计） |
| `/api/services` | GET | 插件、系统服务、NAS 设置、定时任务 |
| `/api/control` | GET | 桌面入口状态、访问地址、当前端口、访问令牌 |
| `/api/control` | POST | `{"enabled": true/false}` 开关桌面入口 |
| `/api/control/port` | POST | `{"port": 5001}` 改端口（渲染配置 + `nginx -t` + reload，失败回滚） |
| `/api/control/token` | POST | 重新生成访问令牌（旧会话立即失效） |
| `/api/plugins` | GET | 已装插件清单（图标、网页路径、可打开性探测，缓存 5 分钟） |
| `/api/files` | GET | 目录列表（`?path=` 省略时返回可浏览的根目录） |
| `/api/files/text` | GET | 文本预览（默认前 256 KB） |
| `/api/files/raw` | GET | 内联预览：只有白名单图片类型会 inline，其余强制 attachment |
| `/api/files/download` | GET | 下载（`Content-Disposition: attachment`） |
| `/api/files/upload` | POST | 上传（原始字节流 + `?path=&name=&overwrite=`），重名返回 409 |
| `/api/files/mkdir` | POST | `{path, name}` 新建文件夹 |
| `/api/files/rename` | POST | `{path, name}` 重命名 |
| `/api/files/delete` | POST | `{paths: [...]}` 移到回收站（一次最多 50 项） |
| `/api/files/trash` | GET | 回收站列表 |
| `/api/files/restore` | POST | `{ids: [...]}` 从回收站恢复 |
| `/api/files/trash/empty` | POST | `{ids?}` 彻底删除（不带 ids 就是清空） |
| `/api/all` | GET | 以上采集类接口的全部内容 |
| `/api/login` `/api/logout` | POST | 浏览器入口的令牌登录/退出 |

## 安装

**方式一：从应用商店装（推荐）**。本插件已在 `scripts/build_apps.py` 的 `PACKAGE_SPECS`
里登记（id `nasconsole`、插件编号 11020、服务端口 18100），推送到 `main` 后 CI 会打包
`apps/nasconsole-<版本>.zip` 并更新 `apps.json`，商店里直接安装即可。商店安装包与下面的
脚本安装**目录结构完全一致**：

```text
/data/plugin/xiaomi-nas-console/
  current -> releases/<版本>-<时间>/     程序、web/、lan/ 入口模板、VERSION
  admin-token                            访问令牌（缺失时服务首次启动自动生成）
  state.json                             端口等运行状态
/home/<用户>/plugin/nasconsole/          UI + INFO + scripts/control（plugin.sh verify 用）
```

**方式二：本机脚本安装**（不经过商店，适合开发调试）：

```bash
cd projects/xiaomi-nas-console
NAS_IP=192.168.1.8 \
NAS_SSH_KEY="$HOME/.ssh/id_ed25519" \
bash deploy/install-on-nas.sh
```

需要：NAS 已开启密钥 SSH、能 `ssh root@NAS`。脚本会：

1. 把程序装到 `/data/plugin/xiaomi-nas-console/releases/<版本-时间>/`，并更新 `current` 软链；
2. 生成访问令牌 `/data/plugin/xiaomi-nas-console/admin-token`（0600）；
3. 安装 `xiaomi-nas-console.service`（最小权限）与两个 nginx 入口；
4. 把带占位符的桌面入口模板放进 release 目录的 `lan/`（单元里的 `LAN_TEMPLATE`
   指向 `current/lan/…`，所以装到哪个 release 都能找到，商店安装包同理）；
5. 注册小米客户端条目，并按 `plugin.sh verify` 的摘要算法补齐
   `/home/<用户>/plugin/nasconsole/`（缺这一步插件开机会被强制卸载）；
6. 启动服务并自检。

可选环境变量：`NAS_USER_ID`、`PLUGIN_ID`（默认 11020）、`LAN_PORT`
（不设就沿用这台机器上已安装的端口，首次安装默认 **5001**）。

安装完成后：电脑浏览器打开手机端显示的地址（默认 `http://<NAS_IP>:5001/`），
粘贴令牌登录；小米客户端需**完全退出再打开**，在「全部应用」里打开「控制台」
（开关、端口、令牌都在那里）。

卸载：

```bash
NAS_IP=192.168.1.8 NAS_SSH_KEY=... bash deploy/uninstall-on-nas.sh   # PURGE=1 连数据一起删
```

### 开机自启

根文件系统是只读 erofs、`/etc` 是 overlay，systemd 在 overlay 挂载前就读完了单元目录，
所以安装时新增的 unit 开机时不在依赖集合里。本仓库的 `community-plugins-boot.sh`
（root crontab 每分钟）会扫描 `/data/etc/upper/systemd/system/` 并补启动其中的
`*.service`——安装脚本已 `systemctl enable`，因此重启后会被自动拉起。
如果那台机器上没装插件市场，需要自行加一条等价的 cron 钩子。

## 限制

- 写操作只有「桌面入口开关」和文件窗口的上传/新建/重命名/删除；**容器与插件启停
  仍然不做**。所有写操作都要过同一套守卫：客户端入口/回环直连视为可信，
  浏览器入口必须已登录并且带 CSRF 令牌。
- 文件浏览与写操作只允许在固定根目录内：`/nas/pool0`、`/nas/mnt/pa0`、`/nas/mnt/pa1`、
  `/nas/sys`、`/home`、`/data`、`/log`。所有路径都会 `resolve()` 之后再判断
  （引擎层还会再查一遍），符号链接指到根目录外同样会被拒绝；单目录最多列 3000 项，
  一次最多删 50 项；存储根本身不能删除或重命名。
- 删除**不是**永久删除：会移到该存储根下的 `.console-trash/`（同盘瞬间完成，
  `index.json` 记录原路径），可以在窗口里恢复；只有「彻底删除」才真的抹掉。
  厂商自己的 `. #trash`（客户端「回收站」）由 filemgr 索引维护，本插件不碰它，
  所以从桌面删的东西**不会出现在小米客户端的回收站里**——它在我们自己的回收站里。
- 内联预览只对白名单图片类型开放（jpeg/png/gif/webp/bmp/avif），其余一律
  `attachment` —— 否则在同源上内联渲染 HTML/SVG 等于给自己开 XSS 口子。
- 浏览目录会读盘（这是用户主动操作）；文件视图**不会自动轮询**，所以不会在后台
  反复唤醒硬盘。
- 浏览器入口是 **HTTP**，令牌在局域网内明文传输——**不要把这个端口转发到公网**。
- 停用桌面入口后端口不再监听；再次启用需要从小米客户端页面操作（或 SSH 调
  `POST 127.0.0.1:18100/api/control`）。
- 未挂载的盘、USB 外接盘也会出现在列表里；判断是否是休眠对象请看 `rotational` 标记。
- 盘温来自内核 `drivetemp`，硬盘休眠时不读；SMART 每次刷新最多 5 分钟缓存。
- CPU 是 4 核 A55：前端刻意用原生 JS、后端只用标准库，避免在 NAS 上跑构建链。
- 电脑端按桌面尺寸设计（≥900px 宽）；手机浏览器打开只会看到一句提示，请用电脑或客户端。
